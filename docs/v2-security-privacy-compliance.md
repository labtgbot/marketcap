# TONBANKCARD V2 Security, Privacy, and Compliance Hardening

Issue: [#38](https://github.com/labtgbot/marketcap/issues/38)

This checklist is the launch gate for public users, Telegram Mini App review, and crypto-adjacent scrutiny. It records the controls that are implemented in code, the controls that must be confirmed operationally before launch, and the abuse cases reviewers should exercise manually.

## Security Checklist

- Browser security headers are emitted by PHP for the public shell: `Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `Cross-Origin-Opener-Policy`.
- Static assets served by Apache receive the non-CSP hardening headers from `.htaccess`, including `X-Frame-Options` and HSTS for HTTPS deployments.
- The Content-Security-Policy defaults to `default-src 'self'`, blocks plugins with `object-src 'none'`, pins `base-uri 'self'`, restricts embedding with `frame-ancestors`, and explicitly allow-lists Telegram, TON Connect, CoinGecko assets, jsDelivr, unpkg, and ChangeNOW surfaces used by the app.
- CSP uses a per-response CSP nonce for public-shell inline script blocks, so `script-src` no longer permits `'unsafe-inline'`.
- CSP still permits `script-src 'unsafe-eval'` because the upstream Vue 2 shell renders server templates with the browser template compiler. Removing that exception requires precompiled Vue render functions or a framework migration.
- CSP still permits `style-src 'unsafe-inline'` for Vuetify runtime styles and legacy inline style attributes. Narrowing that directive requires moving those styles to stylesheet classes or nonce-compatible style blocks.
- JSON API responses inherit non-CSP security headers and remain `Cache-Control: no-store`.
- Cookie-backed write requests to trusted-session user state require `X-TONBANKCARD-CSRF`.
- CSRF tokens are derived server-side from the HttpOnly session token and exposed as a separate response token. The raw session cookie value is not returned in JSON.
- Non-local profiles force HTTP requests to HTTPS by default through `.htaccess` and the PHP front controller; `TONBANKCARD_FORCE_HTTPS=false` is reserved for upstream-managed TLS redirects.
- HSTS emits `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` once HTTPS is confirmed.
- Session cookies are `HttpOnly`, `SameSite=Lax`, and add `Secure` whenever HTTPS is enforced or the active runtime URL is HTTPS.
- JSON request bodies are content-type checked and decoded centrally before route handlers run.
- Route handlers continue to normalize path parameters, coin ids, alert thresholds, preset payloads, and admin settings before persistence.
- Server templates use escaping helpers for output generated by PHP. Vue-owned text is rendered through normal text bindings unless a component has a documented reason to render trusted HTML.
- Provider, bot, admin, Redis, database, AI, and premium signing secrets stay in environment variables or the admin store; no secret is exported into `window.GeckoClient`.
- Local checks include `npm run lint:php`, `npm run test:security-compliance`, and the broader `npm test` aggregate.

## Privacy controls

- Telegram data: Store only the Telegram user id, safe language/premium flags, hashed group context, and validated launch metadata needed for session behavior. Do not persist first name, username, raw `initData`, raw `query_id`, raw `hash`, or raw `chat_instance`.
- Wallet addresses: Treat TON Connect wallet addresses as user-controlled personal data. Keep wallet profile state client-side unless a later feature has an explicit server-side retention reason and deletion path.
- AI feedback: Store feedback with request context and optional session linkage only when needed for quality review. Do not ask users to submit private keys, seed phrases, wallet secrets, or investment instructions.
- Analytics: Keep event payloads limited to route, feature, plan, provider, and coarse state fields. Avoid raw wallet addresses, Telegram usernames, precise location, and free-form personal text in analytics.
- Deletion requests: Support manual deletion by Telegram user id, session hash, wallet address if it is ever persisted, and AI feedback request id. Verify the requester controls the relevant Telegram or admin identity before deleting.
- Retention: Expire sessions on the configured TTL, keep audit logs only as long as operationally necessary, and review AI feedback/exported analytics before public launch.

## Compliance Notes

- Telegram Mini App: The app must use validated `Telegram.WebApp.initData` for trusted user actions, keep launch context minimal, support Telegram web embedding through CSP `frame-ancestors`, and avoid collecting Telegram profile fields that are not needed for the feature.
- TON Connect: The manifest points to the site terms and privacy policy. Wallet connection UI must make clear that wallet addresses are public blockchain identifiers and that the app never needs seed phrases or private keys.
- CoinGecko: Market data views must keep provider attribution visible where market data is shown, honor cache/freshness metadata, and avoid implying that CoinGecko data is investment advice.
- AI: AI summaries, sentiment, and insight cards are informational only. Prompts and response validation must preserve the "not financial advice" posture and expose uncertainty, market data age, and fallback states.
- ChangeNOW: Exchange widget surfaces must disclose that ChangeNOW is a third-party exchange flow, that TONBANKCARD does not custody funds, and that users should review ChangeNOW fees, rates, KYC, jurisdiction, and transaction risks before proceeding.
- Telegram Stars premium: Premium copy and entitlement handling must avoid promising investment outcomes. Refund/support handling follows Telegram Stars platform rules and the documented admin audit process.

## Secret rotation plan

- Rotate `TONBANKCARD_BOT_TOKEN` through BotFather, update runtime secrets, then redeploy. Revoke existing Telegram sessions if token compromise is suspected.
- Rotate `TONBANKCARD_ADMIN_TOKEN` and `TONBANKCARD_ADMIN_SUPPORT_TOKEN` by replacing runtime secrets and invalidating any stored operator copies. Confirm support remains read-only after rotation.
- Rotate `UPSTASH_REDIS_REST_TOKEN`, `COINGECKO_API_KEY`, `GROQ_API_KEY`, `TONBANKCARD_ALERT_WORKER_TOKEN`, `TONBANKCARD_SEARCH_REFRESH_TOKEN`, `TONBANKCARD_TON_CURATION_TOKEN`, and `TONBANKCARD_PREMIUM_SIGNING_SECRET` independently. Update staging first, run readiness checks, then update production.
- Rotate MySQL credentials by creating a new least-privilege user, deploying the new `MYSQL_DSN`, `MYSQL_USER`, and `MYSQL_PASSWORD`, confirming migrations and API health, then revoking the old user.
- After any suspected leak, search CI logs, deployment logs, admin store snapshots, and issue/PR comments for exposed values before closing the incident.

## Manual abuse checklist

- Try browser-initiated cross-site writes against watchlist, alerts, screener presets, and premium endpoints with only the session cookie. Expected result: `csrf_token_required` for JSON writes, or `unsupported_media_type` for plain HTML form posts before any mutation.
- Replay the same requests with a bad `X-TONBANKCARD-CSRF`. Expected result: `csrf_token_invalid`.
- Replay with the session response CSRF token. Expected result: request passes CSRF and then succeeds or fails only on normal session/storage checks.
- Try admin writes with no token, an invalid token, and the support token. Expected result: unauthenticated or read-only failures, never mutation.
- Try large JSON bodies, invalid JSON, wrong `Content-Type`, malformed coin ids, invalid alert thresholds, malformed preset ids, and unexpected enum values.
- Verify session responses do not contain raw Telegram usernames, first names, raw `initData`, `query_id`, raw `hash`, raw `chat_instance`, or the raw session cookie value.
- Inspect browser response headers for the public shell, `/api/health`, `robots.txt`, `sitemap.xml`, and `tonconnect-manifest.json`, and confirm HTTP requests redirect to HTTPS.
- Load the Telegram profile with the Telegram web app script enabled and confirm CSP does not block required Telegram, TON Connect, or ChangeNOW assets.
- Trigger provider failures for CoinGecko, AI, Redis, and ChangeNOW surfaces and confirm the UI falls back without exposing secrets or stack traces.
- Confirm the privacy policy, cookies policy, terms, CoinGecko attribution, AI disclaimer, and ChangeNOW third-party disclosure are reachable from relevant user flows.

## Verification

- `tests/security-compliance-check.sh` verifies the launch-hardening documentation, HTTPS redirect/HSTS controls, header helpers, API header inheritance, CSRF gate, safe session response token, CORS header allow-list, admin write role check, frontend CSRF capture, README link, and npm script wiring.
- `npm run test:security-compliance` runs the focused security/compliance gate.
- `npm test` includes the focused gate in the full reproducible check suite.
